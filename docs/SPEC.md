# KidsLocker — спецификация

Домашний инструмент родительского контроля времени для одного ПК на Windows 11 Pro.
Родитель управляет расписанием, в запрещённые часы компьютер принудительно выключается.

## Условия

- ПК сына: Windows 11 Pro. Учётная запись сына — **локальная, с правами администратора** (по требованию родителя не понижается).
- Родитель управляет удалённо со своего телефона через Telegram-бота.
- Сын **не** получает предупреждений: в запрещённое время комп просто выключается.

## Цель и её честные границы

Пока сын — администратор, абсолютной защиты не существует (это свойство Windows).
Задача KidsLocker — **поднять планку** так, чтобы обход требовал знаний и усилий, и
**сделать любой обход видимым**: родитель получает алерт в Telegram. Абсолютную стенку
даёт только загрузочный слой (BIOS setup-пароль + BitLocker), он описан отдельно и
ставится руками.

## Поведение (петля блокировки)

- Наступил запрещённый интервал → немедленное `shutdown /s /f /t 0`.
- Вход/разблокировка в запрещённое время → выключение за секунды. В запрещённое окно
  сын фактически не может пользоваться Windows.
- В разрешённое время — обычная работа. **Пароль BIOS на включение не нужен** (снимаем;
  оставляем только пароль на вход в настройки BIOS), поэтому утром ничего вводить не надо.

## Архитектура

Одна **служба Windows (`KidsLockerSvc`), работающая от `LocalSystem`**. Стартует при
загрузке, независимо от входа пользователей. Внутри службы:

1. **ScheduleStore** — расписание в JSON. Формат: правила по дням недели, интервалы
   *разрешённого* времени с точностью до минуты, разовые исключения (`+1 час на сегодня`,
   пауза до даты). Файл лежит в `%ProgramData%\KidsLocker\schedule.json`, ACL: запись
   только `SYSTEM` + `Administrators`, читать — все. Служба держит эталон в памяти и сверяет
   файл по SHA-256: правка извне (напр. `"Enabled":false` в Notepad) **откатывается и
   алертит** — легальные изменения идут через Telegram и эталон не ломают.
2. **ScheduleEvaluator** — по текущему локальному времени отвечает: сейчас запрещено?
   когда следующая граница? Время берём из системных часов; смену времени/пояса ловим
   и алертим.
3. **Enforcer** — выполняет выключение; перед этим пишет в журнал и шлёт алерт.
4. **SessionMonitor** — реагирует на вход/разблокировку (события/WTS), чтобы гасить
   попытки войти в запрещённое окно.
5. **TelegramBot** — long-poll `getUpdates`. Команды родителя: статус, показать/изменить
   расписание, `выключить сейчас`, `+1 час сегодня`, `пауза до…`, `снять паузу`.
   Доступ только с заранее прописанного `chat_id` родителя.
6. **TelegramNotifier** — алерты: службу останавливали/удаляли, вход в запрещённое время,
   смена системного времени/пояса, создана новая учётка администратора, загрузка в Safe
   Mode.

### Стойкость (самовосстановление, всё прозрачно — без сокрытия процесса)

- **SCM Recovery**: служба настроена на авто-перезапуск при сбое/убийстве.
- **Задача-хранитель (SYSTEM)** в планировщике раз в минуту проверяет, что служба
  установлена и запущена; если нет — ставит/запускает и шлёт алерт.
- **Дублирующие задачи (SYSTEM)**: независимо от службы, в запрещённые часы тоже гасят
  ПК (belt-and-suspenders на случай, если службу снесли).
- **Safe Mode**: служба прописана в `...\SafeBoot\Minimal` и `\Network`, поэтому запускается
  и в безопасном режиме и там тоже выключает ПК; при старте в Safe Mode шлёт алерт.
- **ACL** на каталог/бинарь/конфиг; попытки правки логируются.

Мы **не прячем** процесс и не мешаем его увидеть в диспетчере задач — это осознанно.
Стойкость строится на правах SYSTEM, избыточности и алертинге, а не на маскировке.

## Приложение-пульт (GUI) и один exe

Всё управление — в **GUI-приложении** (WinForms), а не в скриптах: тот же `KidsLocker.exe`
при двойном клике открывает окно с вкладками (Telegram, Служба, Расписание), а при запуске
как служба работает движком. Отличает роли `Program.Main`: флаги/служба → headless-хост,
без аргументов и интерактивно → GUI.

- **Мастер-пароль** (`Gui/LoginForm` + `Security/PasswordHasher`, PBKDF2): вход в пульт
  закрыт паролем родителя, чтобы сын (тоже админ) им не воспользовался. Хеш — в конфиге.
- **Установщик в C#** (`Setup/Installer`): копирование exe в Program Files, служба (sc.exe),
  задачи (schtasks через XML), ACL (icacls), источник журнала — всё из кнопок, без .ps1.
  Манифест `requireAdministrator` → одно окно UAC на запуск пульта.
- **Правки из GUI** идут в службу через `ServiceControl.ApplyWithReload` (stop → запись →
  start): служба перечитывает файл при старте и принимает его как эталон, поэтому защита от
  подмены не срабатывает на легальные изменения.

## Стек

- **.NET 10 LTS (C#)**, `Microsoft.Extensions.Hosting.WindowsServices` + **WinForms** (GUI).
- Публикация: **self-contained, single-file, compressed** под `win-x64` → один `.exe`
  (~50 МБ), на ПК сына среда .NET не нужна.
- Telegram — прямые HTTPS-вызовы Bot API через `HttpClient` (без внешних зависимостей).

## Компоненты репозитория

```
src/KidsLocker.Service/
  Program.cs               — маршрутизация режимов (GUI / служба / служебные флаги)
  Gui/                     — LoginForm (мастер-пароль), MainForm (вкладки-пульт)
  Setup/Installer.cs       — установка/удаление в C# (служба, задачи, ACL, журнал)
  Scheduling/              — модель, хранилище (+детект подмены), вычислитель, парсер
  Enforcement/             — выключение, сессии, восстановление службы
  Telegram/                — клиент Bot API, бот-команды
  Notifications/           — алерты (журнал + Telegram)
  Security/PasswordHasher  — PBKDF2 для мастер-пароля
install/Publish.ps1        — сборка одного self-contained exe (для разработчика)
tests/KidsLocker.Tests/    — юнит-тесты (расписание, парсинг, пароль, детект подмены)
docs/                      — SPEC, operations, hardening
```

## Режимы запуска (exe)

- без аргументов, интерактивно → **GUI-пульт**.
- (служба) — боевой движок на ПК сына.
- `--console` — прогон движка в консоли для отладки.
- `--dry-run` — вместо выключения пишет «БЫЛО БЫ выключение» (безопасный тест; включается
  кнопкой «Установить (тест)»).
- `--enforce-once [--live]`, `--guard` — для задач планировщика; `--test-telegram`,
  `--telegram-updates`, `--install-eventsource` — служебные.

## Тестирование

- Юнит-тесты на **ScheduleEvaluator** (границы интервалов, полночь, разовые исключения,
  разные дни недели) — чистая логика, без Windows-зависимостей.
- Ручная проверка петли на ПК сына по `docs/operations.md`.

## Явно вне зоны ответственности

- Никаких kernel-драйверов, сокрытия процессов, антифорензики — это вредоносные приёмы,
  они не применяются.
- Что нельзя закрыть в софте при админских правах — закрывается загрузочным слоем руками.
