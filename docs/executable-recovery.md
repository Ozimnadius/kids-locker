# Восстановление программы

Начиная с v0.3.0 установщик сохраняет проверенную резервную копию:
`%ProgramData%\KidsLocker\Recovery\KidsLocker.Recovery.exe`.

Основной файл службы — `%ProgramFiles%\KidsLocker\KidsLocker.exe`. Скачанный файл из «Загрузок» для дальнейшей работы не требуется.

Начиная с v0.4.0 отдельная служба `KidsLockerRecoverySvc` запускает резервный exe с `--recovery-service` от SYSTEM. Она начинает проверку сразу после старта и повторяет её каждые 30 секунд. Обе службы зарегистрированы для SafeBoot Minimal и Network, поэтому восстановление не зависит от сети и планировщика, в том числе в безопасном режиме. Задача `KidsLocker-Recovery` с `--recover` остаётся дополнительной проверкой при обычной загрузке и раз в минуту. Если основного exe нет, она проверяет SHA-256 копии, возвращает файл атомарно и запускает службу. Отсутствующая служба пересоздаётся с основным путём и ранее сохранённым режимом (тест/бой). Расписание, пароль и Telegram не перезаписываются.

Если файл существует, восстановитель его не заменяет: старой копией нельзя откатить обновление. При установке новой версии создаётся новая копия. Работающая основная служба раз в пять минут проверяет резервную копию, резервную службу и задачи; вернуть копию можно только из основного файла с ожидаемой контрольной суммой.

## Обновление и удаление

Для обновления запустите скачанную новую версию и нажмите «Установить (боевой)». Удалять предыдущую версию не требуется.

Кнопка удаления в разделе «Служба» сначала отключает восстановление и удаляет задачи, затем останавливает и удаляет обе службы, их записи SafeBoot и данные. Общая блокировка предотвращает одновременные установку, удаление и восстановление. Без манифеста `Recovery\enabled.sha256` оставшийся восстановитель ничего не делает.

Папки данных и восстановления получают полный ACL с владельцем «Администраторы»: SYSTEM и администраторы могут изменять файлы, обычные пользователи — только читать и выполнять. Ссылки/точки подключения вместо этих папок не принимаются. Новые exe и манифест наследуют защищённые права.

## Ограничения

- Резервная служба должна быть установлена новой версией и разрешена в SafeBoot. Реальная загрузка целевого ПК в безопасном режиме здесь не проверялась; модульные тесты не заменяют такую проверку.
- При удалении обеих копий локальное восстановление невозможно; в обычной Windows может помочь настроенный загрузчик GitHub. Пользователь с правами администратора может отключить все механизмы; абсолютной защиты от него нет.
- SHA-256 выявляет повреждение; это не цифровая подпись против администратора, заменившего одновременно копию и хеш.
- Локальное восстановление не требует интернета. С v0.5.0 доступен независимый загрузчик публичного GitHub: подробности в [описании сетевого восстановления](github-recovery.md).
- Резервная служба проверяет примерно каждые 30 секунд; задача — раз в минуту. При занятой блокировке установки попытка пропускается. Мгновенное восстановление не обещается.

Диагностика `--diagnose` показывает наличие копии, включённость восстановления, её путь, состояние резервной службы и записи SafeBoot для обеих служб. В журнале сохраняются успешное восстановление и ошибки.
