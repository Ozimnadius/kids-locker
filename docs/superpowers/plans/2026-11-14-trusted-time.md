# План: доверенное время и безопасный режим

Основание: согласованное в чате поведение — основной и резервный источник времени в интернете; после перезапуска без подтверждённого времени блокировать компьютер.

Уточнение для v0.2.1: по решению пользователя ожидание первого подтверждения увеличено с 20 секунд до 5 минут. После успешного ответа расписание применяется сразу. Резервная задача перечитывает настройки после ожидания; её лимит выполнения — 6 минут. Описание первоначальной реализации ниже сохранено как история v0.2.0.

Исполнение: самостоятельно в ветке `codex/trusted-time-safe-mode`, затем независимая проверка изменений. Новую рабочую копию не создаём: исходная копия чистая, параллельных изменений нет. Публикация выполняется существующим процессом GitHub Actions по тегу; этот план не запускает выпуск.

## Решения

- TimeAPI.io по HTTPS; резерв — серверная отметка `ts` диагностического HTTPS-ответа Cloudflare. Оба источника проверены живыми запросами; Cloudflare не предоставляет здесь договорённости о точности специализированного сервиса времени. Ответы строго проверяем, ошибки не превращаем в разрешение.
- Время хранится только в памяти службы: UTC из сети плюс монотонный таймер, учитывающий сон Windows. Перевод системных часов не участвует в расписании. Проверка сети каждые 15 минут, без задержки контроля; после успешной проверки потеря сети не сбрасывает часы.
- При запуске даём до 20 секунд на оба источника и повторные попытки. При отсутствии результата запрещаем работу, даже если есть временная пауза. Явное отключение контроля родителем сохраняет своё значение.
- По уточнению пользователя время жёстко задаётся как Москва UTC+3. Выбора пояса нет; старый LastTimeZoneId игнорируется. Паузы с сохранённым UTC-смещением переводятся в Москву.
- Резервная проверка планировщика и пульт запрашивают часы действующей службы через локальный канал с проверкой PID сервера по SCM. Если службы нет — получают время из API самостоятельно. Это предотвращает ошибочное выключение резервной задачей при потере интернета после успешного запуска службы.
- Перезапуск самой службы также требует новой проверки сети. GUI должен получать время до остановки службы для изменения паузы/добавки. Временные команды без проверенного времени отклоняются.
- Исправляем доказанные дефекты: проверка результата выключения; проверка значения SafeBoot и обязательность регистрации; ограничение ожидания вспомогательных процессов. Добавляем журнал ошибок старта и безопасную диагностическую команду без изменения службы.
- Реальный инцидент на ПК сына остаётся неподтверждённым до получения его журналов. Тесты не перезагружают компьютер и не выключают его.

## На что обратить внимание при проверке

- Ошибочные часы могут сломать TLS: проверку сертификатов не отключать, при ошибке блокировать.
- Резервная задача не должна выключать ПК только из-за отсутствия сети, когда служба уже знает время.
- Никакое уведомление, журнал или вспомогательное восстановление не должны мешать выключению.
- Безопасный режим без сети должен запрещать работу после ограниченной попытки проверки времени.
- Проверить, что пакет для GitHub Release остаётся одним самодостаточным exe и не требует файлов SDK.

## Ход работы

- Проверено: на текущем ПК служба и папка данных отсутствуют; журналы инцидента недоступны. TimeAPI.io и Cloudflare отвечают. В PATH есть только среда выполнения .NET, SDK устанавливается локально в игнорируемую папку `artifacts` для тестов.

- Реализация проверена: 131 тест прошёл, предупреждений сборки нет. Полная публикация собирает один самодостаточный exe около 66 МБ.
- Живые запросы через производственный InternetTimeSource: TimeAPI.io HTTP 200, около 0,8 с; принудительное переключение на Cloudflare HTTP 200, около 0,3 с.
- Независимая проверка: исправлены миграция старой паузы с UTC-смещением, доступность /off при отказе API времени и освобождение имени IPC между клиентами. Регрессионные тесты проходят. Гипотеза об удержании старого дескриптора как причине отказа сервера не подтвердилась; её не считаем обнаруженной ошибкой.
- Дефект таймаута ProcessRunner воспроизведён: ожидание заняло 8 секунд при лимите 150 мс; после исправления тест проходит.
- Проверены опубликованный exe в --enforce-once без --live, диагностический отчёт и запуск хоста --console --dry-run с подтверждением времени. Для этих безопасных проверок процесс запущен с обычными правами через временную переменную RunAsInvoker: манифест exe обычно требует повышения. Служба не устанавливалась, выключение и перезагрузка не выполнялись.
- Решение по проверке безопасного режима: без целевого ПК нельзя установить причину именно прежнего инцидента. Исправлены доказанные дефекты и добавлен --diagnose; реальное выключение в безопасном режиме остаётся проверкой на ПК сына.
- Выпуск по тегу не запускался; существующий GitHub Actions сохранён без изменений.
